# BiRead 0.1.27-beta：双语标注与原 PDF 同步

验证日期：2026-10-18。本报告记录发布前验证。本轮修复高亮/划线，不改动解析与翻译缓存版本；保留 0.1.26 的公式与连续阅读修复。安装包已在本地构建，尚未安装到用户的 Zotero。

## 根因与改动

- 词组对齐原先把完整段落送入本地 ONNX 模型，超过 512 token 后直接失败。中文选区因此只能保存为本机标注，无法形成英文和 PDF 标注。现在按翻译结果已有的句子 ID 定位选区，仅对相关句子推理，再映射回整个段落的 UTF-16 偏移。完整句子使用已有对应关系；跨句选区逐句处理，不能确认时不写入不完整的 PDF 范围。
- 原图公式的加载占位文字与隐藏 token 曾一起计入 DOM 选区，导致公式后选词位置偏移。现在公式是一个逻辑 token，图片与占位标签不改变偏移；图片加载和标注刷新保留选区。公式 ID 在模型输入里替换为等长空格。
- 原有英文标注如果保存过空的中文对应范围，会挡住后续重新对齐。现在允许补齐该对应关系；原 PDF 中创建的标注也可使用本地词汇表匹配，不强制依赖模型配置。
- 打开文献后，对源文、译文和段落仍一致的本机中文标注尝试补同步。保留原有颜色、划线/高亮类型和笔记；自动匹配不冒充用户手动确认。
- 规范标注写入 Zotero 后，等待原 PDF 阅读器更新再导航；同步颜色、笔记与删除，串行处理显示更新。轻微坐标舍入和 JSON 属性顺序变化不再使双语关联丢失，真正移动标注仍会使旧关联失效。

## 验证

- 153 项 Node 回归测试通过，0 失败，其中本轮新增 8 项。覆盖长段落末尾、重复词组、双向偏移、跨句选区、公式 token、原有本机中文标注升级、空对应修复、PDF 阅读器更新和坐标舍入。
- TypeScript 主工程、测试工程通过；本轮修改的 TypeScript 文件 ESLint 通过；`git diff --check` 通过。
- 使用用户已经安装的本地 ONNX 模型，只读提取两条失败标注及其缓存译文。旧的整段调用均复现 `Paragraph exceeds model's 512-token limit`；新的句子对齐均成功：
  - “开发了一种高动态、坚固、双稳态的软执行器。” → `develop a highly dynamic, robust, bistable soft actuator`，反向匹配通过。
  - “SMA 驱动的软肢。” → `SMA-driven soft limbs`，反向匹配通过。
- 无界面 Edge 运行真实的 BilingualView、AnnotationControls、AnnotationBridge 和 PageLayout，验证公式加载前后选区一致、刷新不丢选区、中文划线联动英文、英文高亮联动中文、原 PDF API 更新先于导航、对照模式与重新创建控制器后的标注恢复。
- 构建 ZIP 完整性通过；manifest 为 0.1.27-beta，包内包含新对齐与选区处理代码。

## 验证边界与安装

浏览器测试中的 Zotero 数据库和原 PDF 阅读器 API 使用测试替身，不能视为已在用户正在运行的 Zotero 窗口中验收。实际 ONNX 推理使用本机已安装模型，没有调用在线翻译服务；本轮也没有修改用户文献、缓存或现有标注。

没有可靠对应关系的选词仍保留单侧标注，不能保证任意翻译结果都存在精确词组对应。旧本机标注只有在段落原文和译文未变化时才自动补同步。

在 Zotero 插件管理器选择“从文件安装插件”，安装 `dist/release/BiRead-0.1.27-beta.xpi`，重启后重新打开 BiRead。无需清缓存；保留缓存才能恢复之前仅保存到本机的中文标注。
