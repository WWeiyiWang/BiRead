We need to revise the product direction.

I do NOT want:

- screenshots
- OCR screenshots
- exported translated images
- a newly generated bilingual PDF as the primary workflow
- a separate external reading application

I want the translation experience to happen DIRECTLY INSIDE ZOTERO.

The desired workflow is:

1. Open a PDF normally in Zotero.
2. Click "Bilingual Reading".
3. The plugin loads/translates the document.
4. I can immediately read the FULL DOCUMENT as aligned Chinese + English.
5. Highlights and annotations should correspond between Chinese and English.
6. The original Zotero PDF remains the canonical source document.

This should feel like a bilingual mode of the Zotero reader itself.

==================================================
PROJECT STRATEGY
==================================================

Use:

https://github.com/windingwind/zotero-pdf-translate

as the primary plugin foundation.

Do NOT rebuild Zotero integration, providers, settings, translation services, packaging and existing mature infrastructure from scratch.

Also inspect and learn from:

https://github.com/1281300805/zotero-inline-translate

especially its implementation of:

- in-reader translation overlays
- source text coordinate mapping
- translation persistence
- annotation following
- highlight mapping between original and translated views

Do NOT blindly copy incompatible code.

Identify reusable architectural ideas and reimplement them cleanly in the current plugin architecture.

==================================================
CORE FEATURE
FULL BILINGUAL READING MODE
==================================================

Add a button to the Zotero PDF reader:

BILINGUAL

Clicking it should open a bilingual reading representation of the CURRENT PDF.

This should NOT generate a new PDF.

This should NOT require taking screenshots.

This should NOT open an external browser.

The bilingual interface should live inside Zotero.

Possible implementation:

- reader tab sub-mode
- injected reader pane
- custom full-size reader view
- another Zotero-native panel tied to the current attachment

Choose whichever integrates most reliably with the current Zotero reader architecture.

==================================================
READING LAYOUT
==================================================

Default:

LEFT
Chinese translation

RIGHT
Original English

Target ratio:

58% Chinese
42% English

Optional:

50 / 50

Each corresponding paragraph must occupy the same bilingual row.

Example:

--------------------------------------------------

Chinese paragraph

|

Original English paragraph

--------------------------------------------------

Next bilingual block begins only after BOTH corresponding sides are complete.

Use semantic blocks such as:

- title
- abstract
- heading
- paragraph
- list item
- quotation
- figure caption
- footnote where feasible

Do NOT align sentence-by-sentence visually.

==================================================
FULL DOCUMENT BEHAVIOUR
==================================================

I want to be able to translate/read the ENTIRE paper.

When Bilingual Mode starts:

1. extract document structure
2. segment document into semantic blocks
3. display original blocks immediately
4. translate progressively in batches
5. fill Chinese blocks as translations arrive

Do NOT wait for the entire document to finish translating before showing anything.

Display:

TRANSLATING 18 / 136

or another subtle progress state.

The user should be able to start reading page 1 while later blocks continue translating.

==================================================
TRANSLATION CACHE
==================================================

Translation must persist locally.

After a paper has been translated once:

reopening Bilingual Mode should immediately load cached translations.

Do NOT retranslate unchanged blocks.

Cache key should include:

- Zotero attachment/document ID
- block ID
- source text hash
- translation provider
- model
- translation mode
- glossary version

==================================================
MOST IMPORTANT:
BILINGUAL ANNOTATION SYNCHRONISATION
==================================================

I want highlights and annotations to correspond between Chinese and English.

This is a CORE FEATURE, not an optional future idea.

There are two annotation directions.

==================================================
A. ORIGINAL → TRANSLATION
==================================================

If I highlight text in the ORIGINAL English PDF:

Zotero creates the normal canonical PDF annotation.

The plugin must detect the annotation.

Then:

1. determine which bilingual source block it belongs to
2. determine the source text range
3. find the corresponding translated text/range
4. display a linked highlight on the Chinese side

The Chinese highlight is a visual linked representation.

The canonical Zotero annotation remains anchored to the original PDF.

Do NOT create duplicate independent Zotero annotations unless required.

==================================================
B. TRANSLATION → ORIGINAL
==================================================

If I select/highlight Chinese translated text:

the plugin should map that selection back to its corresponding English source span.

Then create a REAL Zotero annotation anchored to the original PDF.

After creation:

English original shows the Zotero annotation.

Chinese translation shows the linked translated annotation.

Therefore:

both sides represent ONE logical annotation.

==================================================
ANNOTATION ID MODEL
==================================================

Create a mapping layer.

Example:

{
  logicalAnnotationID: "...",
  zoteroAnnotationKey: "...",
  blockID: "block-0042",

  source: {
    startOffset: 120,
    endOffset: 184,
    text: "..."
  },

  translation: {
    startOffset: 63,
    endOffset: 101,
    text: "..."
  }
}

The Zotero annotation key identifies the canonical annotation.

The translation-side highlight should always reference that canonical annotation.

==================================================
IMPORTANT ANNOTATION PRINCIPLE
==================================================

Do NOT treat Chinese and English annotations as two independent annotations.

Treat them as:

ONE ANNOTATION
+
TWO REPRESENTATIONS

English PDF:
canonical Zotero annotation

Chinese bilingual reader:
linked visual annotation

This avoids duplicate notes, duplicate colors and sync problems.

==================================================
TEXT ALIGNMENT FOR ANNOTATIONS
==================================================

Paragraph-level correspondence is not enough for precise annotation syncing.

For each translated paragraph, maintain finer-grained internal alignment.

Do NOT display sentence-by-sentence layout.

But internally segment each paragraph into alignment units.

Possible structure:

block-012

sourceSegments:
[
  {
    id: "012-s1",
    source: "...",
    sourceStart: 0,
    sourceEnd: 85,
    translation: "...",
    translationStart: 0,
    translationEnd: 41
  },
  ...
]

This internal alignment may be:

- sentence level
- clause level
- another stable translation unit

The UI still displays one continuous paragraph.

The internal segmentation exists ONLY for:

- annotation mapping
- selection mapping
- terminology correspondence

==================================================
TRANSLATION API OUTPUT
==================================================

For bilingual mode, translation requests should preserve segment IDs.

Example request:

[
  {
    "id": "012-s1",
    "text": "..."
  },
  {
    "id": "012-s2",
    "text": "..."
  }
]

Expected response:

[
  {
    "id": "012-s1",
    "translation": "..."
  },
  {
    "id": "012-s2",
    "translation": "..."
  }
]

Then render translated segments together visually as a single paragraph.

Do NOT ask the model to return freeform translated prose without IDs.

==================================================
HIGHLIGHT COLOURS
==================================================

If a Zotero annotation is:

yellow
red
green
blue
purple

the linked translated highlight should use the same annotation colour.

Use a softer opacity in bilingual reading mode.

Example:

original PDF highlight:
normal Zotero rendering

translated side:
same colour at approximately 18–30% background opacity

==================================================
ANNOTATION HOVER
==================================================

Hovering a highlight in Chinese:

highlight the corresponding English text.

Hovering the English annotation:

highlight the corresponding Chinese text.

Use a subtle temporary emphasis.

==================================================
ANNOTATION CLICK
==================================================

Clicking either representation should open/focus the SAME Zotero annotation.

The annotation sidebar should continue to use Zotero's normal annotation object.

Do NOT invent a separate notes database.

==================================================
ANNOTATION COMMENTS
==================================================

If I write a comment on the Zotero annotation:

the same comment should be available when selecting the Chinese linked highlight.

Do NOT duplicate the comment.

The source of truth is Zotero's annotation item.

==================================================
ANNOTATION DELETION
==================================================

If the Zotero annotation is deleted:

automatically remove its linked Chinese highlight.

If I delete the annotation through the translated representation:

delete the canonical Zotero annotation after confirmation.

==================================================
ANNOTATION EDITS
==================================================

If annotation colour or comment changes:

update the translated representation automatically.

Listen for Zotero annotation changes where possible.

==================================================
ZOTERO SYNC COMPATIBILITY
==================================================

Canonical annotations must remain standard Zotero annotations.

This is important because Zotero annotations need to continue working with Zotero's own library/sync model.

Do not replace Zotero annotations with a proprietary local-only format.

The plugin may store additional translation mapping metadata locally.

When Zotero annotations sync/change:

reconstruct translated highlight representations from:

- Zotero annotation key
- source anchor
- block mapping
- cached translation alignment

==================================================
PDF POSITION MAPPING
==================================================

Preserve enough information to map source text back to the PDF.

Where available store:

- page index
- text position
- PDF text item IDs
- quadPoints / rects
- source offsets
- extracted text identity

Do NOT rely only on paragraph text matching.

Text matching is too fragile.

Use Zotero/PDF.js positional information where accessible.

==================================================
SCROLL SYNCHRONISATION
==================================================

In bilingual reading mode:

scroll both columns together by semantic block.

Do NOT independently scroll Chinese and English by default.

Because paragraphs have different heights:

do NOT use raw pixel synchronisation.

Use block-based layout alignment.

Each bilingual row automatically handles height differences.

==================================================
CLICK TO PDF
==================================================

Add an optional action on any bilingual block:

OPEN IN PDF

Clicking it should jump the normal Zotero PDF reader to the corresponding page/location.

This is useful for:

- figures
- layout
- equations
- page context

==================================================
PDF / BILINGUAL SWITCHING
==================================================

Provide a very simple toggle:

PDF
BILINGUAL

Switching should preserve approximate reading position.

Example:

If I am reading bilingual block 96,
switching to PDF should navigate to the page containing block 96.

Switching back should return to block 96.

==================================================
FIGURES
==================================================

I do NOT need screenshots of pages.

Do not rasterize the document.

For figures:

show a lightweight placeholder/reference in bilingual mode:

FIGURE 4
View in PDF →

Translate the caption underneath.

For MVP this is enough.

Later figure thumbnails may be added if easily available from PDF.js.

Do NOT make screenshot generation part of the translation pipeline.

==================================================
EQUATIONS
==================================================

Do NOT translate mathematical formulas.

Preserve them or show:

[Equation — view in PDF]

Do not send complex equation strings to the translation API unless necessary.

==================================================
REFERENCES
==================================================

Do NOT translate bibliography entries.

Preserve:

years
publication titles
DOIs
URLs

Inline citations must remain unchanged.

==================================================
ACADEMIC TRANSLATION
==================================================

Add:

ACADEMIC MODE

Default instruction:

Translate academic English into precise and natural Simplified Chinese.

Preserve:
- conceptual distinctions
- discipline-specific terminology
- citations
- proper names
- logical relationships
- paragraph structure

Do not summarise.
Do not simplify theoretical claims.
Do not add explanations.
Do not remove ambiguity that exists in the source.

Use the document glossary consistently.
